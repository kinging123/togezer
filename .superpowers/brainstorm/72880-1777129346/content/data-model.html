Key relationships

profiles 1 → habits owns many habits
habits 1 → check_ins one check-in per day max
profiles ↔ friendships symmetric, no pending state (link = accept)
invite_codes → friendships accepting a code creates a row
check_ins 1 → reactions future: react to friends' receipts
profiles 1 → nudges future: poke a friend once/day
★ Why checked_date is a DATE, not a TIMESTAMP: streaks are day-based. If you store a timestamp, a check-in at 11:59pm in one timezone lands on a different calendar date when compared server-side in UTC — breaking streak counts. Storing a plain DATE (the user's local calendar date) sidesteps this entirely. The client sends the date string; the server stores and compares it as-is.
