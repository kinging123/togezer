Two cases the route must handle

Case A — User B already has an account
// app/j/[code].tsx
const { code } = useLocalSearchParams()
const { isSignedIn } = useAuth()

useEffect(() => {
  if (isSignedIn) {
    // Accept immediately
    acceptInvite(code).then(() => {
      router.replace('/(app)')
    })
  } else {
    // Park the code, go sign up
    await AsyncStorage.setItem(
      'pendingInvite', code
    )
    router.replace('/(auth)/sign-up')
  }
}, [isSignedIn])
Case B — User B is new (after sign-up completes)
// features/auth/hooks/usePostSignUp.ts
// Called once after Clerk session is created

export async function handlePostSignUp() {
  // 1. Create profile row in Supabase
  await createProfile()

  // 2. Check for a parked invite
  const code = await AsyncStorage
    .getItem('pendingInvite')

  if (code) {
    await acceptInvite(code)
    await AsyncStorage.removeItem(
      'pendingInvite'
    )
  }

  // 3. Continue to onboarding
  router.replace('/(onboarding)/pick-habit')
}
acceptInvite() — Supabase transaction (Edge Function)
// Called from client with the user's Clerk JWT
// Edge Function runs with service role to do both writes atomically

// 1. Validate code exists, not expired, not already used
const invite = await sb.from('invite_codes')
  .select().eq('code', code).single()

if (!invite || invite.accepted_by || invite.expires_at < now)
  throw new Error('invalid-invite')

// 2. Insert friendship (canonical ordering: smaller id first)
const [a, b] = [userId, invite.created_by].sort()
await sb.from('friendships').insert({ user_a_id: a, user_b_id: b })

// 3. Mark invite as used
await sb.from('invite_codes')
  .update({ accepted_by: userId })
  .eq('id', invite.id)

Pending invite survives sign-up
The invite code is stored in AsyncStorage before redirecting to auth. handlePostSignUp() checks for it and processes it after the Clerk session exists. The user lands in onboarding already connected to their friend.
Acceptance is an Edge Function
The friendship insert + invite mark-as-used must be atomic. The client can't do both safely — if the app crashes between the two writes you get a dangling invite. An Edge Function with the service role key handles both in one call.
Universal links, not custom scheme
togezer://j/9f2k only opens if the app is installed. https://togezer.app/j/9f2k works in every context — iMessage, WhatsApp, browser — and falls back to a web page with an App Store link if uninstalled.
The domain needs a minimal web host
You need togezer.app to serve the two .well-known files and a fallback page at /j/:code. A Supabase Edge Function or a single GCP Cloud Run container is enough — no full web app needed.
During development — universal links don't work in Expo Go or the simulator without a real domain. Use exp+togezer://j/9f2k (Expo's dev scheme) for local testing. The same app/j/[code].tsx route handles both; only the scheme prefix changes.
